# Duet — ksim 游戏层 · 设计文档

> 把"贴世界观的自由 RP"升级成"像《女骑士模拟器》那样的游戏"。
> 日期 2026-06-14。用户决策：属性走 **AI 判定增量**；主 NPC 世界卡预设；时间=叙事周数；场景系统。

## 1. 现状 vs 目标
现状：世界卡只做 lore RAG（调性/设定符合），**无游戏机制**。
目标：加**游戏层**——属性/经验/状态、周数时间、场景、世界卡主 NPC，事件→数值变化，房间里像游戏一样显示。

## 2. 四个系统

### 2.1 属性系统 ⭐（核心，AI 判定增量）
- **数值 schema**（来自抽取的术语表，现成）：
  - 基础：职业、冒险者等级、等级、经验、力量、敏捷、智力、意志、金钱、支出
  - 淫乱向经验：淫乱、欲望、阴道/口腔/胸部/菊穴 开发+经验、高潮/露出/受虐/精液/百合/自慰 经验、各种"中毒"
  - 状态：list[str]（如 "监禁:哥布林 5"、"露宿街头"、"女神的加护(已失效)"）
  - 好感度：dict[NPC名→int]（会长/教官…）
- 存 `room_members.stats`（JSON，玩家为主；NPC v1 不带）。建房/选角时用世界卡默认表初始化。
- **AI 判定增量**：每个 RP 回合（或玩家行动）后，一个"裁判"脑调用看本回合发生了什么 → 输出 JSON 增量 `{"经验":+160,"淫乱":+1,"口腔经验":+3,"状态_add":["监禁:哥布林 5"],"状态_del":[],"好感度":{"会长":+2}}` → 应用到玩家 stats → 持久化 → 广播 `stats_changed` + 一条变化日志（像游戏"口腔经验+3 淫乱+1"）→ 前端刷新属性面板 + 显示增量。
  - 成本控制：裁判调用按"玩家发言后的回合"跑（不是每个 NPC 台词都跑）；空增量={}时不显示。
  - 升级：经验够则等级+1（简单阈值规则，可选）。

### 2.2 时间系统
- `room.time_week`（int，默认 1）。房间头部显示"第 N 周"。
- ⏩推进时间 = 导演跳时间时 `time_week += N`（导演给 N），叙述这段时间。

### 2.3 场景系统
- `room.scenes`（JSON list）+ `room.current_scene`。每场景有名字 + 该场景的 active NPC 集。
- 切场景 → active NPC = 该场景的；导演**只调当前场景的 active NPC**。
- 导演可把别的 NPC（旧场景的/新的）**引入当前场景**（introduce already 支持，加 scene 归属）。
- 切回旧场景 → 触发"这段时间(按 time_week 流逝)这里发生了啥"补叙（导演）。
- v1 可简化：场景=一个字符串标签 + 每 NPC 一个 `scene` 字段；导演按当前场景过滤。

### 2.4 世界卡主 NPC 预设
- 世界卡定义"主 NPC 名册"（ksim：武道家/会长/教官/哥布林村长… 从抽取内容挑）。
- 选世界卡建房时**自动创建主 NPC**（created_by_ai，active）→ 开局 NPC 不为 0。
- 导演仍动态加新 NPC。

## 3. 搭建顺序（AI判定增量已定）
1. **属性系统**（schema + room_members.stats + 裁判增量 + 房间属性面板 + 变化日志）← 先做，核心
2. **世界卡主 NPC 预设**（选 ksim 即有主 NPC）
3. **时间系统**（周数显示 + ⏩ 推进 +N 周）
4. **场景系统**（场景标签 + 导演按场景过滤 + 跨场景引入 + 切回补叙）

## 4. Phase 1 实现（属性系统）
- 模型：`room_members.stats`（Text/JSON，nullable）。默认 schema 在 `app/stats.py`（DEFAULT_STATS + 字段定义）。建房/选角初始化。
- `app/stats.py`：默认表；`apply_delta(stats, delta)`（数值加/状态增删/好感度合并，纯函数）；裁判 `async judge_stat_delta(scene_text, current_stats, brain)`→ JSON 增量。
- ws：玩家发言后的回合末（或导演拍后），跑 judge_stat_delta → apply → 持久化 member.stats → 广播 `{type:"stats", user_id, stats, delta}`。
- REST：GET /rooms/{id}/cards 带 stats（或单独 GET stats）。
- 前端：房间属性面板（像游戏左栏：基础+经验+状态+好感度）+ 增量浮现日志。
- 评测：加"数值合理性"探针（增量贴合剧情、不乱给）。

## 5. 风险
- 裁判每回合一次脑调用 = 成本；按玩家回合跑、空增量跳过。
- 数值不如原游戏精确（AI 判定，用户已接受换灵活）。
- schema 大；前端面板要可折叠。
- NPC 也带 stats 是 v2（v1 只玩家）。
