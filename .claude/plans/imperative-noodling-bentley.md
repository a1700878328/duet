# 游戏系统全面规划

## 现状诊断

**当前所有系统的核心问题：一切都靠 AI 自觉，没有机械约束。**

| 系统 | 现状 | 问题 |
|------|------|------|
| 时间 | 只有 label 变化 | 推进没有 gameplay 反馈 |
| 金钱 | AI 说给才给，月末才扣 | 99% 时间毫无存在感 |
| 状态 | 字符串列表 `["监禁:哥布林 5"]` | 没有结构化处理 |
| 物品 | 字符串列表 `["生锈短剑"]` | 没有数量/类型/效果 |
| 属性 | AI 裁判每拍发 JSON 增量 | 格式松散，无验证 |
| 任务 | 有代码但靠 AI 发隐藏标记 | 不稳定，你说删了 |

---

## 设计方案

### 一、结构化 JSON Schema（所有系统的基础）

当前所有游戏数据存在两个地方：
- `RoomMember.stats` → `dict[str, Any]` 无验证
- `Room.scenes_meta` → `dict[str, Any]` 无验证

**改成 Pydantic model + JSON 存储**，用一个统一的结构：

```python
class CharacterSheet(BaseModel):
    # 基础属性
    职业: str = "冒险者"
    冒险者等级: str = "E"
    等级: int = 1
    经验: int = 0
    力量: int = 10
    敏捷: int = 10
    智力: int = 10
    意志: int = 10
    金钱: int = 100
    负债: int = 0

    # 淫乱向开发（AI 裁判驱动）
    淫乱: int = 0
    欲望: int = 0
    阴道开发: int = 0
    口腔开发: int = 0
    # ... 全部 NUMERIC_FIELDS

    # 结构化子对象
    物品栏: list[Item] = []        # ✅ 改：从字符串数组改为 Item 对象
    状态: list[StatusEffect] = []  # ✅ 改：从字符串数组改为 StatusEffect 对象
    好感度: dict[str, int] = {}

class Item(BaseModel):
    id: str        # 唯一标识
    name: str      # 显示名
    type: str      # 武器/防具/消耗品/任务道具/贵重品
    quantity: int = 1
    description: str = ""
    effects: dict[str, int] = {}  # {"力量": 2, "淫乱": -1} 等

class StatusEffect(BaseModel):
    id: str        # "监禁:哥布林"
    name: str      # 显示名 "哥布林监禁"
    days: int = 0  # 持续天数
    severity: int = 1  # 1-5 严重程度
    source: str = ""   # 来源（怪物名/事件名）
```

这样 `stats` 就是一个有验证的 JSON，不再是 `dict[str, Any]`。

### 二、时间推进 → 事件系统（核心改动）

**现有问题**：时间推进只是改 label，没有反馈。

**改动方案**：每次 `_advance_time()` 时触发一系列机械检查：

```
_advance_time(steps):
  for each step:
    1. 更新时钟
    2. 检查时间带 → 入夜后触发"夜晚事件"概率
    3. 检查当前场景 → 野外/洞窟/魔王城触发"遭遇事件"概率
    4. 监禁 tick（已有）
    5. 饥饿/疲劳 → 自动消耗金钱（吃饭）
    6. 如果天亮了 → 旅店结算
    7. 如果到月末 → 租金+利息（已有）

事件概率：
  安全场景（公会/城镇/酒馆）→ 低概率社交事件
  危险场景（森林/洞窟/野外）→ 高概率怪物遭遇
  深夜场景 → 特殊夜间事件
```

**事件表**（json 配置，非 AI 驱动）：
```python
class TimeEventTable:
    """按场景+时段配置的随机事件表，纯机械触发。"""
    events: dict[str, list[dict]] = {
        "森林@夜晚": [
            {"type": "encounter", "npc": "哥布林", "weight": 0.6},
            {"type": "encounter", "npc": "兽人", "weight": 0.3},
            {"type": "find", "item": "药草", "weight": 0.1},
        ],
        "城镇@正午": [
            {"type": "social", "npc": "酒馆老板娘", "weight": 0.4},
            {"type": "social", "npc": "借贷商人", "weight": 0.2},
            {"type": "nothing", "weight": 0.4},
        ],
        "洞窟@任意": [
            {"type": "encounter", "npc": "史莱姆", "weight": 0.5},
            {"type": "encounter", "npc": "触手怪", "weight": 0.3},
            {"type": "find", "item": "矿石", "weight": 0.2},
        ],
    }
```

**触发流程**：
1. 时间推进 → 检查当前场景+时段 → 按权重 roll 事件
2. 命中事件 → 广播给前端（"你在森林里遇到了一群哥布林！"）
3. 事件决定是自动战斗判定还是让玩家回应
4. 玩家回应后 → `judge_stat_delta` 正常结算

### 三、金钱系统

**现有问题**：没收入来源、没支出渠道、AI 不管就啥也不发生。

**改动**：

每日自动支出：
- 食宿：每天住旅店扣 10g，睡野外扣 5g（但可能被袭击）
- 装备维护：每 7 天扣 15g（AI 可免除或追加）

自动收入：
- 完成任务后自动结算奖励（已有代码，只是要保证必触发）
- 战斗胜利后自动掉金钱（1d10+等级*2）
- 卖物品直接到账

债务系统强化：
- 负债 > 0 时，每天自动产生利息（5% 日息）
- 负债 > 100 时，借贷商人主动在城镇场景出现
- 负债 > 300 时，强制触发卖身/卖器官事件
- 还不起→监禁/卖娼/结局

### 四、物品栏系统

**现有问题**：就是一个字符串数组，没法交互。

**改动**：

```typescript
// 前端类型
interface InventoryItem {
  id: string;
  name: string;
  type: "武器" | "防具" | "消耗品" | "任务道具" | "贵重品" | "素材";
  quantity: number;
  description: string;
  equippable: boolean;
  usable: boolean;
  effects?: Record<string, number>;  // 装备/使用时的属性效果
  icon?: string;  // emoji 或图标名
}
```

前端 UI 交互：
- **查看物品栏** → 列表显示全部物品，按类型分组
- **使用** → 消耗品使用后生效（回复HP、加buff）
- **装备** → 武器/防具装备到身上，改变属性
- **丢弃** → 移除物品
- **给予** → 送给 NPC（加好感度）

后端 hooks：
- `use_item(item_id)` → 检消耗品，应用效果，广播 stats 变化
- `equip_item(item_id)` → 装备武器/防具，修改对应属性
- `add_item(item, count)` → 自动叠加同 ID 物品
- `remove_item(item_id, count)` → 减数量或删除

物品来源：
- 战斗胜利自动掉
- 商店购买
- AI 通过 `[[给予:{"物品":["..."]}]]` 发放
- 宝箱/探索发现

### 五、状态效果系统

**现有问题**：`"监禁:哥布林 5"` 这种字符串没法结构化处理。

**改动**：

```python
class StatusEffect:
    id: str          # 唯一标识
    name: str        # 显示名
    group: str       # 分组：监禁/怀孕/诅咒/契约/标记
    source: str      # 来源NPC名
    days: int        # 已持续天数
    severity: int    # 1-5 严重程度
    effects: dict[str, int]  # 属性修正 {"意志": -2, "淫乱": 3}
    escape_dc: int   # 逃脱难度（监禁类用）
    description: str # 显示描述
```

内置效果（机械处理，不依赖 AI）：
- **监禁:X** → 每天意志-1、淫乱+1，severity 提升 → 第 7 天触发结局判定
- **怀孕:X** → 第 30 天生产，期间体力-2、淫乱+2
- **负债** → 每天利息 5%，借贷商出现
- **契约:娼妇** → 每天随机接客、金钱+5 但淫乱+1
- **公共厕所** → 每天强制事件、意志-1
- **淫纹** → 所有快感类经验+50%

### 七、实施路线

分 3 个阶段，每阶段可独立上线：

**Phase 1 — 数据层改造**（无 UI 变化）
- 定义 `CharacterSheet` Pydantic model
- 定义 `Item`、`StatusEffect` model
- 改 `stats.py` 用 model 存取
- 现有 AI 裁判照常工作，输出自动转成结构化数据

**Phase 2 — 时间事件系统**
- 事件表配置
- `_advance_time` 内触发检查
- 简单的事件→广播机制

**Phase 3 — UI 交互**
- 物品栏 UI
- 装备栏 UI
- 事件弹窗
